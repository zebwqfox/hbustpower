# 生成正式签名并导出备案所需的公钥与指纹

备案要填"应用公钥"和"应用签名（MD5）"，两者来自**发布包的签名证书**。密钥一旦丢失就无法再发布同一应用的更新，请自行妥善备份。

> 我不会替你生成密钥或设置口令：口令属于你本人的凭据。下面是你在本机执行的完整步骤。

## 一、生成发布用密钥库（只做一次）

在 `android` 目录的**上一级**（即仓库根目录）执行，避免密钥被打进项目：

```powershell
& "C:\Program Files\Java\jdk-26.0.2.1\bin\keytool.exe" -genkeypair -v `
  -keystore hbustpower-release.jks `
  -alias hbustpower `
  -keyalg RSA -keysize 2048 -validity 10000 `
  -storetype PKCS12
```

执行时会依次要求：

1. **密钥库口令**：自己设定并记牢，不要用于其他用途。
2. **姓名/组织/城市等信息**：个人开发者可填姓名与所在城市，组织可填个人名称；这些信息会写进证书，备案与商店会看到。
3. 确认信息后生成 `hbustpower-release.jks`。

**备份**：把 `.jks` 文件与口令分别保存在两个地方（例如密码管理器 + 离线备份）。丢失后无法更新已上架的应用。

## 二、让 Gradle 使用该密钥

在 `android/` 下新建 `keystore.properties`（已在 `.gitignore` 中，不会进版本库）：

```properties
storeFile=../hbustpower-release.jks
storePassword=你的密钥库口令
keyAlias=hbustpower
keyPassword=你的密钥口令
```

然后打包：

```powershell
cd android
.\gradlew.bat clean testDebugUnitTest assembleRelease
```

产物：`app/build/outputs/apk/release/app-release.apk`。
若 `keystore.properties` 不存在，release 包会退回 debug 签名，**那种包不能用于备案或上架**。

## 三、导出备案要填的签名信息

```powershell
cd android
.\tools\Get-FilingSignature.ps1 -Apk .\app\build\outputs\apk\release\app-release.apk
```

脚本会在 `filing\签名信息.txt` 写入并在屏幕打印：

- 证书主题、颁发者、序列号、有效期、签名算法、公钥算法与长度
- **应用签名**：MD5、SHA-1、SHA-256（带冒号大写 + 去冒号小写两种写法）
- **应用公钥**：Base64 与 HEX 两种形式
- 证书 PEM（个别平台要求上传证书文件）

也可以直接从密钥库读取（会提示输入口令，口令不会写入文件）：

```powershell
.\tools\Get-FilingSignature.ps1 -Keystore ..\hbustpower-release.jks -Alias hbustpower
```

生成的 `签名信息.txt` **只含公钥和指纹，不含私钥或口令**，可以安全地复制到备案表单。

## 四、常见问题

- **平台要的是哪种公钥格式？** 多数平台接受证书公钥的 Base64；若表单明确写 `SubjectPublicKeyInfo`，用脚本输出的 PEM 证书执行 `openssl x509 -in cert.pem -pubkey -noout` 取。
- **MD5 要不要冒号？** 两种都给了，按表单示例格式填。
- **签名换了会怎样？** 备案信息与实际安装包不一致会被驳回；换签名需要更新备案信息，已上架应用还会无法覆盖安装。
- **之后每次发版**：版本号变化一般不需要重新备案，但签名必须保持一致。
