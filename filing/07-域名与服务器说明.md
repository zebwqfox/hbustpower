# 域名与服务器怎么填

本应用没有后端业务服务器，也没有账号体系：用户数据直接来自学校官方系统，只保存在手机上。开发者侧有一个**静态站点**，放隐私政策网页和一个版本/公告文件；另有一个只接收匿名统计的接口（用户可在同意隐私政策前或之后随时关闭）。业务数据（账号、宿舍号、电量）一律不经过它。下面是备案表单里"服务器 IP""域名"这类必填项的处理方式。

## 一、事实描述（可直接用于说明栏）

> 本应用为客户端工具，开发者未部署任何业务服务器与数据接口，不接收、不存储用户数据。应用运行时访问湖北科技学院及其指定身份验证服务商（超星）的官方站点读取用户本人数据，数据仅显示在用户设备本机。开发者持有一个静态网站（`hbustelec.imfurry.com`），用于展示隐私政策与应用介绍，并存放一个供客户端读取的版本与公告文件（内容仅为版本号、更新说明、下载地址、公告文字与功能开关，不含任何用户数据）；同一域名下有一个仅接收匿名使用统计的接口，该功能在应用内以独立开关明示告知、用户在同意隐私政策前即可关闭，收集范围为应用版本、系统版本、设备型号、处理器架构、语言、渠道与应用自生成的随机安装标识，不含设备唯一标识与任何业务数据，数据存放于境内服务器且不出境。客户端读取该文件时不携带 Cookie、参数或设备标识；发现新版本时仅提示用户，安装包由用户自行在浏览器中下载安装，应用不具备代码热更新能力。

## 二、需要准备的域名

即便没有业务服务器，实际办理中仍建议准备一个**自己的域名 + 已完成网站 ICP 备案的静态站点**，原因：

1. APP 备案通常需要通过"接入服务提供者"（云厂商）提交，平台会核验你在该平台有可关联的网络资源。
2. 应用商店上架普遍要求隐私政策提供**公网可访问链接**。
3. 备案通过后的备案号，通常也要求在官网与应用内展示。

最小成本方案：

- 注册一个域名（`.com` / `.cn` 均可，`.cn` 须实名）。
- 在国内云厂商买最低配的对象存储或轻量服务器托管静态页面。
- 先完成**网站 ICP 备案**（备案主体与 APP 备案主体保持一致），再提交 **APP 备案**。
- 把 `filing/html/privacy-policy.html` 和 `user-agreement.html` 上传上去，链接填进备案表与商店后台。
- 把 `cloud/config.example.json` 改好后作为 `config.json` 放到同一个域名下，地址写进 `android/gradle.properties` 的 `cloudConfigUrl`。
- 安装包（APK）体积较大，放对象存储；把该存储的域名写进 `cloudDownloadHosts`，应用只接受这些域名的下载地址。

## 三、表单填写建议

| 表单项 | 建议填法 |
|---|---|
| 服务器放置地 | 中国内地（静态站点所在地区）`【待填】` |
| 服务器 IP / 实例 | 静态站点的 IP 或对象存储所在实例 `【待填】` |
| 域名 | `imfurry.com`（业务子域 `hbustelec.imfurry.com`） |
| 域名证书 | 域名注册商提供的证书文件 `【待填】` |
| 是否使用 CDN | 按实际情况；用了 CDN 要选对应的接入服务商 |
| 应用数据存储说明 | 见上文"事实描述" |
| 更新检查地址 | `https://hbustelec.imfurry.com/app/config.json` |
| 统计上报地址 | `https://hbustelec.imfurry.com/api/v1/report`（用户可随时关闭） |
| 安装包分发地址 | `https://cdn-imfurry.imfurry.com/update-release/`（同主体的 CDN / 对象存储） |

## 四、不要做的事

- 不要为了凑表单而虚构服务器或填写他人资源。
- 不要把学校的域名（`hbust.edu.cn`）或超星的域名填成"本应用的域名"——那不是你的资源，主体不符会被驳回，也可能给学校带来麻烦。
- 不要在未取得学校同意的情况下，宣传本应用为学校官方应用。
- 不要把更新检查做成"下发可执行代码"或"远程改接口地址"：那属于热更新与动态配置业务逻辑，会让"是否含热更新"一项由否变是，审核口径完全不同。当前实现只下发版本号、文字与开关，请保持这个边界。
