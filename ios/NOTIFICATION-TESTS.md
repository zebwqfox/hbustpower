# 低电量提醒验证 · 1.4.1

2026-09-05，Xcode 27 / iOS 26.5 iPhone 17 Pro 模拟器。测试使用隔离的 UserDefaults 和虚构电量，不连接学校账户。

## 自动检查：27 项通过

- 高于或等于 20 度不提醒；20 → 19.99 度触发一次。
- 首次读取就是 12.50 度、零度或负电量均可提醒。
- 持续低电量重复刷新不重复发送；充值回升后再次变低重新提醒。
- 首次通知权限允许、拒绝、拒绝后再允许、临时授权和临时 App Clip 权限分支。
- 发送失败和权限接口失败不会消耗提醒，后续更新可以重试。
- 重启仍保留已提醒状态；修改提醒值、切换宿舍、重置账户时按新条件判断。
- 无效阈值和非数值电量被拒绝；10 次重叠检查只发送一次。
- 从真实 AppModel 的数据更新方法进入通知链路，并检查标题、电量文字与声音配置。
- 首次启动先请求权限，已授权或已拒绝再次启动不重复请求。

## 系统实际投递：通过

在模拟器使用测试专用 provisional 权限，通过真实 AppModel → LowBalanceReminder → UNUserNotificationCenter 发送本地通知，确认收到本次新增通知。

通知正文：当前剩余 12.50 度，低于 20 度提醒值。

前台通知代理允许 banner、list、sound。测试确认的是系统投递；未把临时授权的静默通知等同于真机横幅、声音或锁屏体验。

## 复现

Debug 构建运行参数：

```text
--ui-preview --low-balance-preview --verify-alerts --verify-system-alert
```

日志成功标记：`ALERT_CHECK COMPLETE: 27 checks passed` 与 `SYSTEM_ALERT_CHECK PASS`。

权限组合由可控通知中心测试；系统投递另行使用真实 iOS 服务验证。普通预览不会申请权限或发送提醒，只有显式系统通知测试参数会启用测试授权。测试代码不包含在 Release 中。

## 修复原因与使用范围

旧版把“看到低余额”当成“已提醒”，首次拒绝权限后持续低电量会漏提醒；发送错误也未处理。新版仅在系统接受通知请求后记为已提醒，失败或未授权时保留下次尝试机会。

通知检查发生在启动、回到前台或手动刷新成功取得数据后。应用不在 iOS 后台持续轮询学校电量。
